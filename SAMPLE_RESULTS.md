## 🐍 Sample Track 1: Python Full-Stack Developer (Mid-Level)

### Question 1: Core Python Fundamentals
**Question**: *"How does the Global Interpreter Lock (GIL) affect multithreading in Python, and when would you use multiprocessing or asyncio instead?"*

**Candidate Answer**:
> *"The GIL is a mutex that prevents multiple native threads from executing Python bytecodes at once. For CPU-bound tasks, multithreading doesn't provide true parallelism because only one thread holds the GIL at a time; in those cases, I use the multiprocessing module to spin up separate processes with independent memory spaces. For I/O-bound operations like network requests or database queries, threads release the GIL while waiting, but asyncio is usually even better because it provides single-threaded cooperative multitasking with lower memory overhead."*

**AI Evaluation**:
- **Score**: `9.5 / 10`
- **Strength**: *"Exceptional distinction between CPU-bound vs I/O-bound workloads, accurate explanation of GIL bytecode locking, and clear architectural rationale for choosing asyncio over multiprocessing."*
- **Weakness**: *"Could briefly mention recent subinterpreter progress (PEP 684/free-threaded Python 3.13) as a forward-looking detail."*
- **Improvement**: *"Reference the new free-threaded mode in Python 3.13 to showcase bleeding-edge ecosystem awareness."*
- **Ideal Answer Key Points**:
  - Definition of GIL as a CPython mutex
  - Multiprocessing for CPU-bound parallelism
  - Asyncio / threading for I/O-bound concurrency

## 🤖 Sample Track 2: AI & LLM Engineer (Senior)

**Candidate Answer**:
